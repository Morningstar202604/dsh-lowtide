## 这是什么

lowtide 是装在 [DeepSeek Harness (dsh)](https://github.com/deepseek-ai/dsh) 上的一个插件，干一件事：**把"下任务"和"跑任务"在时间上拆开。**

你白天想到什么活儿，随手扔进队列，审一遍放行，然后该开会开会、该睡觉睡觉。到了你设定的闲时窗口，它自己批量跑完。你回来，活儿在那儿，报告也在那儿。

几个硬指标先摆在这：

- **四种执行策略**：单次、迭代、采样、复核——从"一遍过"到"跑五份让我挑"都覆盖
- **168 项单元测试 + 10 个端到端 spec**，CI 四矩阵（ubuntu / windows × node 22 / 24）全绿
- **桌面端、网页端同一份构建产物**，装一次两端通用
- 闲时执行落在 DeepSeek 低谷价区间，**约半价**，部分模型峰谷价差最高 1100%

## 你会怎么用：几个真实场景

**场景一：下班前十分钟。**
你review完今天的代码，顺手把三个明天想做的任务填进工单：一个重构（迭代策略，3 轮）、一个写周报（单次）、一个拿不准方案的让它跑 4 份候选（采样）。全部 ✓ 放行。关机走人。明天早上到工位，打开晨报：重构做完了，周报在候选目录里，4 份方案并排摆着等你挑——每份花了多少钱写得清清楚楚。

**场景二：周末全天低谷。**
周五晚上把攒了一周的杂活一口气排进去：清理依赖、补测试、跑数据脚本。周末两天全天都是低谷价，你出去玩，它在家干活。周一回来看报告验收，不合格的点 retry，合格的合并。

**场景三：高峰时段的灵感拦截。**
上午十点你正在跟 Agent 聊一个紧急 bug，顺手又想让它"顺便把文档也更新了"。拦截卡这时候弹出来：现在跑是高峰价，投到闲时队列晚上跑是半价，差多少钱直接写给你看。你点一下"投递闲时队列"，草稿一个字不丢，接着聊你的 bug。

**场景四：挂在常开服务器上（L3 全自动）。**
你有一台 24 小时开着的机器跑 dsh。切成 L3 档，之后从任何地方通过 API 投任务（`POST /ds-lowtide/tasks`），它到点自动跑、自动出报告。完全无人值守，但沙箱权限、日预算、文件锁定这些保险丝一个不少。

**场景五：重要交付物要有人兜底。**
要给客户发的方案，用复核策略：先跑一遍，再自动开一个独立会话，以你指定的"审查关注点"（比如"专挑数据来源的硬伤"）把结果重新挑一遍刺。你早上看的不是裸结果，而是结果 + 一份挑剔的审查意见。

**场景六：海外党。**
你在旧金山，DeepSeek 的"高峰"是北京时间——对你来说其实是前一天下午。设置页直接把这些时段换算成你的本地时钟给你看，一键采用。你只管按自己的作息设窗口，账目永远跟官方对齐。

## 它是怎么工作的

```
① 投递              ② 裁定              ③ 执行                 ④ 验收
你有空时：           队列面板按工作区      到达闲时窗口：          你忙完回来：
拦截卡一键投递        分组展示，逐条        预检五关全部通过        打开执行报告——
或手动填工单     →   ✓批准 ⏸顺延  →    才进沙箱执行       →  结果 + diff + 实花
（四种策略可选）      ✕放弃 / 全部放行     每个窗口只跑一批        + 省了多少钱
```

任务的一生：`pending-review → queued → preflight → running → done / failed / stale / timeout`，外加 `deferred`（顺延）和 `dropped`（软删，随时可恢复）。

注意第二步——**裁定**。这是 lowtide 和"全自动脚本"最大的区别：每条任务必须经过你亲手批准（或者你在 L2 档的批次确认门上统一放行）才会执行。机器永远没有权力把自己投进运行队列。自动化的是执行，不是决策，所以我们敢说"你可以放心地不在场"。

![settings](./assets/screenshots/settings.png)

闲时窗口几点到几点、一批最多跑几个任务、单个任务最长多久、跨工作区开几个并发、每天最多花多少钱、报告留多少份、自治开到哪一档、价格表要不要自己覆盖——全部是图形界面。官方定价规则（包括周末全天低谷那条新规）也在这一页用人话解释了一遍。

### 还有三个界面，藏在日常动线里

- **价格胶囊**（会话头部）：现在是忙时还是闲时、距离下一批开跑还有多久、队列里压着几个任务，扫一眼就知道。点它直接改窗口。
- **忙时拦截卡**：高峰时段你在输入框打字它就弹出来——"现在跑"还是"投递闲时队列"，价差多少写在明面上。你的草稿一个字不丢，烦了可以今天不再打扰。
- **执行报告（晨报）**：开门见山先告诉你这次省了多少钱，然后异常置顶、采样候选并排等你挑、历史报告随时翻、一键复制成 Markdown 发给别人。

## 工作区：这是最容易被忽略、但最重要的一个选择

每个任务都必须落在某个**工作区**（workspace）里执行。这个选择直接决定了三件事：

1. **它能动哪些文件。** 任务在沙箱里跑，沙箱的边界就是工作区目录（`lt-standard` 档是 workspace-write）。选错工作区，轻则找不到文件，重则改了不该改的东西。
2. **它跟谁排队。** 同一个工作区内的任务是**串行**的（防止两个任务同时改一个仓库），不同工作区之间**并行**（上限可调，默认 3）。想提高吞吐，把不相关的任务撒到不同工作区；想保住顺序，放在同一个里。
3. **报告和队列怎么分组。** 队列面板、晨报都按工作区归组，活儿一多你就知道这个设计多救命。

**怎么选：** 工单弹窗里的 Workspace 下拉有三个来源——

- **Use current workspace**：就用你当前会话所在的工作区，最常用；
- **列表里的已有工作区**：每个都带绝对路径，一眼认出是哪个项目；
- **Custom path…**：手填一个路径，临时给个新目录跑活。

如果你选了"续接前序会话"（Continue previous），还要再选一次工作区和里面的具体会话——任务会接着那个会话的上下文继续干，适合"昨天没聊完，今晚接着来"。

我们的建议：**一个项目一个工作区，别混。** 预检里的 git 快照和文件锁定都按工作区生效，混着放容易把自己绕进去。

## 四种执行策略，什么时候用哪个

| 策略 | 它干什么 | 什么时候用 | 费用 |
|---|---|---|---|
| **单次** | 跑一遍就完，跟普通 Agent 任务一样 | 简单明确的活儿 | 1× |
| **迭代** | 同一会话连跑 2–5 轮，每轮按你给的"迭代眼光"审查并改进上一轮；相邻两轮足够像（bigram 相似度 > 0.9）就判定收敛，提前收工 | 需要打磨的东西：文章、方案、代码 | 约 N× |
| **采样** | 2–5 个互不可见的独立会话各跑一份完整结果，并排展示、标明各自花费，**由你挑**——机器不替你做审美判断 | 标题、创意、设计方案：你要的是选项不是答案 | 约 N× |
| **复核** | 跑完之后另开一个独立会话，按你的"审查关注点"把结果重新挑一遍刺，输出审查意见 | 重要交付物，发出去之前再过一道 | 约 2× |

## 自治三档：你想放多少权，自己定

| 档位 | 行为 | 什么时候切 |
|---|---|---|
| **L1 per-task** | 每条任务都要你单独 ✓ 才跑 | 刚开始用、仓库很重要的时候 |
| **L2 batch**（默认） | 任务进待审，批次开跑前 30 分钟弹确认门，一次全部放行；不放行就一律不跑 | 日常用这个 |
| **L3 full-auto** | 投递即入队，到点直接在沙箱里跑，零确认（切换时要二次确认） | 常开服务器，彻底托管 |

单任务还能在工单里临时覆盖全局档位——比如全局 L2，某条不重要的任务单独放 L3。

## 架构：为什么它敢无人值守

说实话，让 Agent 在你不在场的时候跑批任务，是个挺吓人的事。lowtide 敢这么做，靠的是四层工程设计。

**第一层：Cordis 微内核。** dsh 本身跑在 Cordis 微内核插件体系上——所有能力都是插件，插件之间通过服务注入通信，互不直接依赖。lowtide 的宿主半就是一组标准的 Cordis 服务：路由、调度器、状态机各司其职，注册进内核，随 harness 启动，也能干净地卸载。我们不是挂在 dsh 外面的一层皮，而是长在内核里的一个正经器官。

**第二层：宿主半 + 浏览器半，一次构建，双面产物。** 宿主半（Node.js）负责调度、执行、账本；浏览器半（React）负责全部界面。两端共享同一份构建产物——桌面版 dsh 的 GUI 本身就是 Web 渲染，所以桌面端和网页端**不需要两个分支，行为完全一致**。你在桌面版配的窗口，网页版打开就是同一个状态文件。

**第三层：平台无关核心层 `lowtide-core`。** 窗口模型、价目表、计费公式、队列汇总、账本、批次窗口计算——这些核心逻辑全部是不依赖 dsh 任何 API 的纯函数，独立成包、独立测试。好处很实在：核心逻辑可以拿 44 个纯函数单测往死里测，而且哪天你想把它移植到别的 Agent 框架，这个包拆出来就能用。

**第四层：不信任任何输入的防御链。**

- **预检五关**：工作区还在不在、git HEAD 变没变、锁定文件 sha256 对不对、窗口装不装得下、预算够不够——任何一关不过，标 `stale` 或自动顺延，绝不盲跑。
- **fail-closed 权限档**：`lt-readonly / lt-standard / lt-trusted` 三档沙箱预设，审批全部置 never——无人值守意味着没人能点"允许"，所以能做的不能做的，开跑前就圈死了。
- **原子写入 + 损坏自愈**：状态文件原子保存，写坏了自动回退备份。清空已完成任务？账本的数字一分不少。
- **同源 + loopback 信任围栏**：HTTP 路由只认本机同源请求，跨站调用直接拒。

状态同步走 SSE 增量推送，断了自动降级 4 秒轮询——队列动一下，界面立刻跟着动。

## Quick Start

前置：Node `^22.19 || >=24`，pnpm `11.7`。所有依赖都在公共 npm registry，不需要任何私有源。

**第一步：装 dsh（二选一）**

- 桌面版：从 DeepSeek 官方渠道装 dsh Desktop（自带完整运行时 + Web UI）；
- 命令行版：`npm install -g @deepseek-ai/dsh`。

然后在 dsh 的模型设置里配好一个可用模型（比如 DeepSeek 官方 API Key）。lowtide 自己不碰你的任何凭据。

**第二步：拉源码，构建，装进去**

```powershell
git clone https://github.com/KelaoHu/dsh-lowtide
cd dsh-lowtide
pnpm install

# 先构建核心层（插件的测试依赖它的产物）
pnpm --filter lowtide-core bundle
# 再构建插件：宿主半 + 浏览器半一次出齐
pnpm --filter dsh-lowtide bundle

# 装进 profile——桌面端网页端用同一份产物
npx @deepseek-ai/dsh@0.1.0-rc.7 plugin --profile desktop add ./packages/dsh   # 桌面端
npx @deepseek-ai/dsh@0.1.0-rc.7 plugin --profile web add ./packages/dsh       # 网页端

# 起开发实例（3080 端口）
pnpm --filter dsh-lowtide dev
```

装完打开 dsh，会话头部应该能看到价格胶囊，输入区旁边有队列面板。看不到就翻翻 FAQ。

## 使用说明（手册级）

### 投递任务的三条路

1. **拦截卡**（最顺手）：高峰时段正常打字，拦截卡弹出来，点"投递到闲时队列"——你正写的草稿原样变工单。
2. **手动工单**（最完整）：点输入区旁的"New"，提示词、策略、轮数、优先级随便填，高级设置里还有模型 / 推理强度 / 会话模式 / 锁定文件。
3. **API**（最极客）：`POST /ds-lowtide/tasks`，接进你自己的任何自动化系统。

### 队列面板的日常操作

- 按工作区分三栏：**待执行 / 已结束 / 已放弃**。
- 每条任务行内操作：✓ 批准、⏸ 顺延到下个窗口、✕ 放弃（软删，随时能捞回来）。
- 批量：「全部放行」一次批完；「清空已完成」保持清爽（账不受影响）。
- 「Run now」：不等窗口，立刻跑一批。调试和演示都靠它。

### 时间语义（这块建议读一遍）

| 时间 | 按什么判定 | 说明 |
|---|---|---|
| 官方忙时段（默认） | **北京时间** | DeepSeek 按北京时间收费，账要跟官方对齐；周末全天闲时 |
| 自定义忙时/闲时窗口 | **你的本地时间** | 支持跨零点、按星期；价格带实时预览 |
| 闲时运行窗口 | **你的本地时间** | 窗口结束只是不再启动新任务，不打断正在跑的 |

### 每日账本

`ledger[YYYY-MM-DD] = { yuan, savedYuan }`。实花、省了多少，按天累计。显示价就是计费价，同一个公式算出来的，逐位可核对。

## HTTP API

前缀 `/ds-lowtide/`，同源 + loopback 信任围栏：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/state` | 聚合状态（价格/倒计时/队列/最新报告） |
| GET | `/events` | SSE 增量推送（客户端降级 4s 轮询） |
| GET/PUT | `/config` | 读/写配置 |
| POST | `/tasks` | 投递工单 |
| POST | `/tasks/:id/approve \| defer \| drop \| cancel \| retry \| restore \| delete \| choose-candidate` | 裁定与管理 |
| POST | `/tasks/approve-all` | 全部放行 |
| POST | `/estimate` | 测算：峰价 vs 谷价 |
| POST | `/batch/run-now` | 立即开跑 |
| POST | `/dismiss` | 今日不再拦截 |
| GET | `/health` | 心跳 |

## 权限档

| preset | sandbox | approval |
|---|---|---|
| `lt-readonly` | read-only | never |
| `lt-standard` | workspace-write | never |
| `lt-trusted` | danger-full-access | never |

投递 UI 不提供选择，任务统一按 `lt-standard` 执行；其余两档留给 API 调用（`POST /tasks` 传 `permissionPreset`）。过了预检才跑，绝不盲跑。

## 数据与状态

- 一切持久化在 `$DSH_HOME/lowtide.json`（原子写入，损坏自动回退备份）；进程有 `DSH_PROFILE` 时按 profile 隔离。**同一时刻只让一个实例写同一个文件**——桌面版和 Web 版别同时开，或者开好 profile 隔离。
- 每窗口只跑一批，跨零点安全；空队列不产空报告。
- 顺延恢复：窗口开始时，预检顺延的任务自动重新入队（≥3 次标失败）；你手动顺延的回到待裁定。

## 安全说明

- 路由有 Host/Origin 信任围栏（只认 loopback + 同源）；**别把 3080 直接暴露公网**，远程用 SSH 隧道或鉴权反代。
- Windows 端沙箱是缓解级（partial），Linux/macOS 是完整强制。无人值守场景建议叠加文件白名单和日预算。
- L3 全自动：投递即入队，闲时零确认直接跑——切换前有二次确认。
- 状态文件里有完整任务提示词和路径，备份注意保管。
- 发现漏洞请走 [SECURITY.md](./SECURITY.md) 的私密渠道。

## 常见问题

**窗口到了为啥没跑？**
按顺序查：任务批了没 → "暂停闲时批处理"勾了没 → 批次确认门放了没 → 预算是不是用完了 → 预检是不是挂了（任务变 `stale`，详情页有原因）。

**采样为啥不自动选最好的？**
故意的。机器不替你做审美判断，候选和花费并排摆给你，你点"选这份"。

**我在国外，忙时对不上我的作息？**
官方价按北京时间收。设置页会显示官方时段在你本地长什么样；想按自己作息来就自定义窗口，或者点"一键采用官方忙时（换算到我的时区）"。

**估算和实花对不上？**
估算只按输入 token 上界粗算（不含输出），实花按真实 usage（含输出和缓存命中）。报告里两个数都查得到。

**任务变 stale 了？**
预检挂了：工作区没了、git 快照变了、锁定文件被改了、预算不够、窗口装不下。详情页看 `lastError`，修好点 `retry`。
